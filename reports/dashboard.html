3. Difficulty, measured with scripted players (200 seeded games each)

Two scripted players play the real game logic at 60 updates per second. The tracker always moves toward the lowest correct number and sidesteps the nearest threat when none is on screen; the random mover picks a new target every half second. Neither is a human; the tracker is an upper bound on what the level parameters allow, the random mover a floor.

4. Logic tests (no browser)

11 of 11 passed, 0 failed, 57 ms, run 2026-10-17 08:00 (tests/results/unit-latest.tap; regenerate with npm run test:tap).
  • equations: every level produces equations whose stated answer is the only solution among the choices
  • equations: level forms match the concept (one-step / two-step / both sides)
  • equations are reproducible with a seed and vary without one
  • game: start resets score, lives and level and shows an equation
  • game: keyboard input moves the basket and it stays inside the screen
  • game: catching the correct number scores and gives a new equation
  • game: catching a decoy or bomb costs a life; 0 lives → lost
  • game: timer running out ends the game
  • game: clearing a level adds a time bonus, then next level, then win after level 3
  • game: the correct answer is guaranteed to appear within three spawns
  • game: objects that fall past the bottom are removed; a missed correct answer emits 'miss'

8. Limitations

  • The difficulty figures come from scripted players, not people; a human play-testing session (the brief's step 11) is still to be recorded.
  • The browser play test is quoted from its recorded run; sound is verified only by the mute toggle.
  • Decoy "closeness" is measured, not its effect on real players.

Reproduce

npm test → npm run test:tap (records the logic run) → npm run dashboard (seeded audit and simulations run inside the build, about 5 s). This file embeds its figures and screenshots.
